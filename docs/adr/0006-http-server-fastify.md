# ADR-0006: HTTP 서버 프레임워크 — Fastify

- **날짜**: 2026-10-22
- **상태**: 결정됨

## 배경

백엔드는 같은 저장소 `server/` 의 별도 Node 프로세스로 REST + WebSocket(`ws`)을 제공한다.
REST 부분을 받칠 프레임워크가 필요했다. WebSocket 은 학습 목적상 프레임워크 플러그인(`@fastify/websocket` 등)을 쓰지 않고
**`http.Server` 의 `upgrade` 이벤트에 `ws` 를 직접** 붙인다.

## 선택지

|                | Express                   | **Fastify (채택)**                       | Hono                            |
| -------------- | ------------------------- | ---------------------------------------- | ------------------------------- |
| 실무 인지도    | 가장 높다                 | 높고 성장 중                             | 엣지 환경 중심으로 성장 중      |
| TypeScript     | 타입이 덧붙여진 형태      | 좋다                                     | 매우 좋다                       |
| 내장 기능      | 거의 없다 (미들웨어 조립) | 로깅(pino), 스키마 검증, 플러그인 캡슐화 | 웹 표준 `Request`/`Response`    |
| `ws` 직접 부착 | `server.on('upgrade')`    | `fastify.server.on('upgrade')`           | `@hono/node-server` 서버에 부착 |

## 결정

**Fastify.** 로깅과 스키마 검증이 기본이라 "실무형 서버" 구성을 보여주기 좋고, Express 다음 선택지로 실무에서 가장 많이 언급된다.
세 후보 모두 `ws` 를 `upgrade` 이벤트에 직접 붙이므로 **WebSocket 학습 목적은 동일하게 달성**된다 — 차이는 REST 쪽 개발 경험뿐이다.

## 결과

- 얻는 것: 요청 로깅·검증·에러 처리의 기본 틀, 모듈별 플러그인 캡슐화
- 잃는 것: Express 의 압도적인 예제·자료량
- 주의: 입력 검증은 `shared/` 의 zod 스키마로 통일한다 (Fastify 의 JSON Schema 와 이중 정의하지 않는다)
